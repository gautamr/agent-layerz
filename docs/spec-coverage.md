# Spec coverage

Which Rust test proves each requirement of `docs/LAYERING-SPEC.md` (decision-39: `test/` may go
only when no requirement lacks a Rust test; TASK-55.9.5). Built from the spec and the Rust tests
under `crates/`. The guard test `crates/alz-test-support/tests/spec_coverage.rs` keeps it true:
it fails on a missing row, a stale row, a duplicate row, a status that is not one of the four,
a named test that is not a test function in `crates/`, and a summary that is out of date.

## Anchors

An anchor is one of these, outside code fences:

1. a `##` or `###` heading, written `§<number>` with the heading's number (`§4.3`);
2. a paragraph that opens with a bold lead, that is a line that starts with `**`, written
   `§<number> <lead>` with the number of the heading it stands under (`§0` before the first
   heading) and the text between the first two `**`, as the spec writes it (`§4.3 Writing.`);
3. a numbered item of section 13, written `§13.<n>`.

A paragraph, bullet or table that has no bold lead belongs to the nearest anchor above it. So a
section without bold leads (§6, §7.13) is one anchor, however long: its row is `gap` until the gap
task walks it and the spec gets sub-anchors.

## Statuses

- `covered`: the Rust tests that prove it, as `path::test_name` (a path from the workspace root).
  Marked only where the named tests assert the requirement; when in doubt the row is `gap`.
- `n/a`: text that states no behaviour (a definition, a rationale, a container heading), with the
  reason.
- `planned`: behaviour the spec marks as not built, or that is another task's work (the Codex adapter, TASK-18), with the task that builds it.
- `gap`: behaviour that lacks a test, named. TASK-55.9.6 to TASK-55.9.9 fill the gaps of their
  sections (`gap_task` in the guard maps a section to its task).
